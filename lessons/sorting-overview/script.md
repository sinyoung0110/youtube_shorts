# 정렬 알고리즘 한눈에 비교 — 대본 및 검산

- 대상: 처음 배우는 알고리즘 학습자
- 영상 길이: 약 61초
- 핵심 질문: 데이터마다 정렬법이 다른 이유는?

## 왜 필요한가

정렬은 크기만 빠르다고 끝나지 않습니다. 메모리, 안정성, 입력 분포, 최악 시간 보장 중 무엇이 중요한지에 따라 선택이 달라집니다.

## 예시와 단계

입력: `비교 정렬 vs 범위·자릿수 활용`

1. 작고 거의 정렬 → 삽입
2. 최악 성능 보장 → 병합·힙
3. 작은 정수 범위 → 계수

## 특징

- 전제: 안정성·메모리·분포·최악 시간 요구를 먼저 정함
- 시간: 비교 정렬 일반 하한 Ω(n log n) · 특수 조건 정렬은 범위 활용
- 공간/안정성: 제자리: 삽입·선택·힙·퀵(스택 제외) · 보조 공간: 병합·계수·기수·버킷
- 장점: 조건에 맞추면 속도와 메모리를 함께 조절
- 한계: 모든 입력에서 가장 빠른 단일 정렬은 없음

## 핵심 의사코드

```text
choose_sort(data):
    inspect_size_and_order()
    check_key_range_or_digits()
    choose_memory_and_stability()
    select_algorithm()
```

## 열 가지 정렬 비교 표

시간은 평균·최악 또는 조건부 복잡도임을 구분하세요. `n`은 원소 수, `k`는 키 범위 또는 버킷 수, `d`는 자릿수, `b`는 기수입니다.

| 정렬 | 시간 | 추가 공간 | 안정성 |
| --- | --- | --- | --- |
| 버블 | O(n²) avg/worst | O(1) | 안정 |
| 삽입 | O(n²) avg/worst | O(1) | 안정 |
| 선택 | O(n²) | O(1) | 불안정 |
| 병합 | O(n log n) | O(n) | 안정 |
| 힙 | O(n log n) | O(1) | 불안정 |
| 퀵 | avg O(n log n) | 스택 | 불안정 |
| 계수 | O(n+k) | O(k) | 구현별 |
| 기수 | O(d(n+b)) | O(n+b) | 안정 패스 |
| 버킷 | 기대 O(n+k) | O(n+k) | 구현별 |
| 셸 | 간격별 상이 | O(1) | 불안정 |

거품 정렬 최선은 조기 종료 최적화 시 O(n), 삽입 정렬 최선은 O(n)입니다. 퀵 정렬 최악은 O(n²), 버킷은 분포가 치우치면 최악 O(n²)입니다. 계수 정렬은 이 표의 출력형 구현은 불안정하며, 누적 개수 기반으로 배치하면 안정적으로 구현할 수 있습니다.
