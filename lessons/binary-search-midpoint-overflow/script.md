# 대본 및 계산 검증

## 대본

### 00:00–00:08.9 · 경고 훅

이진 탐색의 가운데, 무심코 low 더하기 high 나누기 2로 구하나요? 큰 배열에서는 이 한 줄이 위험할 수 있어요.

### 00:08.9–00:29.7 · 오버플로우 예시

예를 들어 32비트 signed 정수에서 low가 15억, high가 20억이면 둘 다 범위 안입니다. 하지만 합은 35억. Java int에서는 오버플로우로 음수가 되어 mid도 음수가 되고, 잘못된 인덱스를 만들 수 있습니다. C의 signed overflow는 결과 자체가 정의되지 않습니다.

### 00:29.7–00:41.7 · 안전한 계산

안전한 계산은 low 더하기 high 빼기 low 나누기 2. 인덱스처럼 low가 0 이상이고 high가 low 이상이면, 차이를 먼저 구해 덧셈이 범위를 넘는 일을 피합니다.

### 00:41.7–00:58 · 언어 차이와 마무리

Python 정수는 고정 32비트가 아니라 필요에 따라 커지지만, 메모리가 무한한 건 아니죠. 시스템 언어의 큰 인덱스에서는 안전한 식을 쓰세요. 작은 디테일이 신뢰할 코드를 만듭니다. 구독하고 코딩 디테일 챙겨가세요!

첫 문장 직후 짧은 합성 경고음을 넣었습니다.

## 수치 검산

32비트 signed `int` 범위는 −2,147,483,648부터 2,147,483,647입니다.

| 항목 | 계산 | 결과 |
| --- | --- | ---: |
| low | 1,500,000,000 | 표현 가능 |
| high | 2,000,000,000 | 표현 가능 |
| 두 경계의 합 | 3,500,000,000 | 최대값 초과 |
| Java `int`의 합(2³² 단위 wrap) | 3,500,000,000 − 4,294,967,296 | −794,967,296 |
| Java의 위험한 mid | −794,967,296 / 2 | −397,483,648 |
| 안전한 mid | 1,500,000,000 + (500,000,000 / 2) | 1,750,000,000 |

Java 정수 나눗셈은 0 방향으로 버립니다. C signed overflow는 정의되지 않은 동작이므로 위 wrap 계산은 Java `int`에만 해당합니다. 안전 공식은 이진 탐색의 인덱스처럼 `0 ≤ low ≤ high ≤ INT_MAX`인 범위에서 `high - low`와 최종 mid가 표현 가능한 것을 전제로 합니다. Python 정수는 고정 폭이 아니어서 이 예처럼 32비트 덧셈이 wrap 되지 않지만, 메모리와 실행 시간은 유한합니다.

## 핵심 코드

```java
int mid = low + (high - low) / 2;
```

`high - low`를 먼저 계산한 뒤 그 절반을 `low`에 더합니다. 다만 임의의 signed 경계값까지 무조건 안전하다는 뜻은 아닙니다. 인덱스가 음수가 아니고 `low <= high`인지, 사용 자료형이 범위를 담을 수 있는지 확인해야 합니다.
