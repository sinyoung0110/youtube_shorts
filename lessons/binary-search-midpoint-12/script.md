# 대본 및 계산 검증

## 대본

### 00:00–00:08.5 · 문제
key 12의 인덱스를 찾아보죠. 두 mid 공식은 처음에 다른 칸을 선택합니다. 경로와 결과를 비교해 볼게요.

### 00:08.5–00:15.3 · 두 공식
첫 mid는 아래쪽, 둘째는 위쪽 가운데예요. C의 정수 나눗셈은 소수를 버립니다.

### 00:15.3–00:30.3 · 아래쪽 mid
아래쪽 mid. 0부터 9는 mid 4, 값 19라 right 3. 다음 mid 1, 값 3이라 left 2. mid 2의 값 5라 left 3. mid 3의 값 12. 찾았습니다. index 3을 반환합니다.

### 00:30.3–00:45.5 · 위쪽 mid
위쪽 mid는 5, 값 20이라 right 4. mid 2의 값 5라 left 3. 구간 3부터 4는 mid 4, 값 19라 right 3. 다음 mid 3의 값 12. 이번에도 index 3을 반환합니다.

### 00:45.5–01:00 · 결과
첫 mid는 4와 5로 달라요. 그래도 둘 다 네 번 비교해 index 3을 찾습니다. 정렬 배열 검색 시간은 오 로그 엔. 위쪽 mid는 mid를 남기는 탐색에서 진행에 유용해요.

## 값별 추적

배열 `A = [1, 3, 5, 12, 19, 20, 22, 25, 29, 31]`은 오름차순이며 인덱스는 0부터입니다. 찾는 값은 `12`입니다.

### 공식 1: 아래쪽 가운데

`mid = left + (right - left) / 2`

| 비교 | left | right | mid | A[mid] | 판단 및 갱신 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 0 | 9 | 4 | 19 | `12 < 19` → `right = 3` |
| 2 | 0 | 3 | 1 | 3 | `12 > 3` → `left = 2` |
| 3 | 2 | 3 | 2 | 5 | `12 > 5` → `left = 3` |
| 4 | 3 | 3 | 3 | 12 | 일치 → `return 3` |

확인 순서는 `19 → 3 → 5 → 12`입니다.

### 공식 2: 위쪽 가운데

`mid = left + (right - left + 1) / 2`

| 비교 | left | right | mid | A[mid] | 판단 및 갱신 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 0 | 9 | 5 | 20 | `12 < 20` → `right = 4` |
| 2 | 0 | 4 | 2 | 5 | `12 > 5` → `left = 3` |
| 3 | 3 | 4 | 4 | 19 | `12 < 19` → `right = 3` |
| 4 | 3 | 3 | 3 | 12 | 일치 → `return 3` |

확인 순서는 `20 → 5 → 19 → 12`입니다. 첫 mid가 4와 5로 다르지만, 두 방식 모두 네 번 비교하고 같은 인덱스 3에서 찾습니다.

## 핵심 코드 형태

```c
int span = right - left;
int mid = left + (span + (upper_mid ? 1 : 0)) / 2;

if (A[mid] == key) return mid;
if (key < A[mid]) right = mid - 1;
else left = mid + 1;

return -1;  // left > right일 때만 도달
```

- `upper_mid == 0`: 아래쪽 mid, 공식 1
- `upper_mid == 1`: 위쪽 mid, 공식 2
- 이 문제처럼 경계를 `mid - 1`, `mid + 1`로 갱신하면 두 mid 모두 진행합니다.
- `left = mid`처럼 mid를 구간에 남기는 변형에서는 위쪽 mid가 경계가 2개 남았을 때 정체를 피하는 데 유용합니다.
- 이진 탐색은 정렬된 배열이 전제이며 시간 복잡도는 `O(log n)`, 반복문 추가 공간은 `O(1)`입니다.
