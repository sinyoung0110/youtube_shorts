# 이진 탐색 트리 — 대본 및 검산

- 대상: 처음 배우는 알고리즘 학습자
- 영상 길이: 약 50초
- 핵심 질문: 찾을 때마다 절반씩 버리려면?

## 왜 필요한가

정렬 배열은 빠르게 찾지만 중간 삽입이 비쌉니다. BST는 비교 결과에 따라 왼쪽·오른쪽 가지로 내려가며 탐색과 삽입을 연결합니다.

## 예시와 단계

입력: `삽입 순서 8, 3, 10, 1 · 찾기 6`

1. 8에서 시작
2. 6 < 8 → 왼쪽 3
3. 6 > 3 → 오른쪽 비어 있음 → 없음

## 특징

- 전제: 왼쪽 < 노드 < 오른쪽 순서 유지
- 시간: 평균 탐색·삽입 O(log n) · 최악 O(n)
- 공간/안정성: 재귀 스택 평균 O(log n), 최악 O(n)
- 장점: 정렬된 순서 순회와 유연한 삽입
- 한계: 입력 순서가 나쁘면 한쪽으로 기울어짐

## 핵심 의사코드

```text
def search(node, x):
    if node is None or node.key == x:
        return node
    if x < node.key:
        return search(node.left, x)
    return search(node.right, x)
```

## 내레이션 및 장면표

| 00.0–11.3s | 값을 찾을 때 매번 절반씩 후보를 버리고 싶지만, 배열은 중간 삽입이 번거롭죠. 이진 탐색 트리는 비교 방향을 가지로 저장해 검색과 삽입을 돕습니다. | 왜 필요한가 |
| 11.6–25.5s | 8을 루트로 넣고 3은 왼쪽, 10은 오른쪽, 1은 3의 왼쪽에 둡니다. 6을 찾으면 8보다 작아 왼쪽 3으로, 3보다 커 오른쪽으로 갑니다. 그 자리가 비어 있으니 6은 없습니다. | 숫자 예시 |
| 25.8–34.9s | 코드에서 현재 노드가 비었거나 값이 같으면 멈춥니다. 작으면 left, 크면 right로 재귀 호출해 한 번에 한 가지씩 따라갑니다. | 핵심 코드 |
| 35.2–49.6s | 균형이 좋을 때 평균 탐색과 삽입은 로그 엔이지만, 정렬된 순서로만 넣으면 높이가 엔이 되어 최악은 선형입니다. 회전으로 균형을 보장하는 AVL과 달리 기본 BST는 스스로 균형을 맞추지 않습니다. | 복잡도와 선택 기준 |
