# 장면별 타임라인

| 시간 | 내레이션 / 핵심 | 화면과 검산 |
| --- | --- | --- |
| 0–4초 | 정렬 배열에서 9 찾기 | 첫 화면에 배열 `[-1, 0, 3, 5, 9, 12]`, target 9 표시 |
| 4–13초 | `lo=0`, `hi=5`, `mid=2`, `A[2]=3<9` | index 2를 강조. `lo=mid+1=3`으로 갱신, 왼쪽 후보를 흐리게 |
| 13–21초 | 남은 범위 3–5, `mid=4`, `A[4]=9` | `lo=3`, `mid=4`, `hi=5`; index 4에서 찾고 return 4 |
| 21–37초 | 반복문 코드를 읽고 각 조건의 역할 설명 | 7줄 코드에 현재 설명 중인 줄을 순서대로 강조 |
| 37–48초 | 후보 수가 절반씩 줄어 `O(log n)` | `16→8→4→2→1`; 최선 `O(1)`, 평균·최악 `O(log n)`, 16개 최대 5번 mid 확인 |
| 48–54초 | 배열 이진 탐색과 BST 재귀 검색의 차이 | 배열은 `lo/hi` 인덱스, BST는 `node.left/right`; 판단 원리는 닮았지만 구조는 다름 |

## 계산 검산

- 시작: `lo=0`, `hi=5`, `mid=(0+5)//2=2`, `A[2]=3`; `3<9`이므로 `lo=3`.
- 다음: `lo=3`, `hi=5`, `mid=(3+5)//2=4`, `A[4]=9`; `return 4`.
- 목표가 있는 이 예시에서 가운데 확인은 2회. 각 반복에서 `==`와 `<`의 상수 개수 비교를 할 수 있으므로 Big O는 반복 수로 설명합니다.
- 길이 16의 최악은 최대 `⌊log₂16⌋+1=5`번 가운데 확인. 최선은 첫 mid에서 찾을 때 1회.
