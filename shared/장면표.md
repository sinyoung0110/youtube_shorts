# 장면별 타임라인

| 구간 | 내레이션 요지 | 화면 / 검산 값 |
| --- | --- | --- |
| 0–3초 | 정렬된 목록에서 27을 찾아볼게요. | 첫 프레임에 질문과 목표값 27 |
| 3–7초 | 숫자를 하나씩 보는 대신 가운데부터 봅니다. | 정렬 배열 전체, 인덱스 0–8 |
| 7–14초 | 가운데 23은 27보다 작네요. 왼쪽은 볼 필요가 없어요. | 인덱스 4의 23 표시; `[4, 9, 13, 18, 23]` 흐리게 |
| 14–21초 | 남은 네 개의 가운데 31은 27보다 큽니다. 오른쪽을 제외해요. | 인덱스 6의 31 표시; `[31, 36, 42]` 흐리게 |
| 21–26초 | 남은 숫자는 27 하나. 세 번 만에 찾았습니다. | 인덱스 5의 27 강조, 총 비교 횟수 3 |
| 26–33초 | 범위를 절반 가까이 줄여요. 그래서 O(log n)입니다. 목록은 정렬되어야 해요. | 정렬 조건과 O(log n), 약 33초 마무리 |

## 값 검산

1. 시작 범위 인덱스 0–8, 가운데 인덱스 4의 값 23. `27 > 23`이므로 `low = 5`.
2. 남은 범위 인덱스 5–8, 가운데 인덱스 6의 값 31. `27 < 31`이므로 `high = 5`.
3. 인덱스 5의 값 27을 찾아 세 번 비교합니다.

`O(log n)` 설명은 정렬되어 있고 가운데 비교로 범위를 좁히는 이진 탐색에 대한 점근적 설명입니다. 이 배열/목표의 실제 비교 횟수는 3회입니다.
