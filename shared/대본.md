# 이진 탐색: 정렬된 백만 개에서 찾기

**영상 길이:** 58초 · **화면:** 세로 9:16, 1080×1920 · **음성:** Supertonic 3 M1 남성 음색, 한국어 오프라인 TTS

## 대본

### 00:00–00:07 · 왜 필요한가
정렬된 기록이 백만 개. 하나씩 찾으면 최악엔 백만 번. 더 빠른 방법은 없을까요?

### 00:07–00:14 · 핵심 생각
이진 탐색은 가운데를 비교해 필요 없는 절반을 버립니다. 정렬돼 있어야 가능해요.

### 00:14–00:26 · 숫자로 추적하기
9를 찾죠. 처음 인덱스는 0에서 5, 미드는 2. 값 3은 작으니 왼쪽을 버려 로우를 3으로. 다시 미드 4, 값 9. 인덱스 4를 반환합니다.

### 00:26–00:39 · 핵심 코드
코드의 로우와 하이는 포함 범위. 로우가 하이 이하인 동안 미드를 계산해요. 같으면 반환, 작으면 로우는 미드 더하기 1, 크면 하이는 미드 빼기 1. 범위가 비면 마이너스 1.

### 00:39–00:49 · Big O
후보가 절반씩 줄어 최악은 오 로그 엔. 백만 개도 스무 번 이내. 첫 미드에 찾으면 오 원. 반복문 추가 공간도 오 원입니다.

### 00:49–00:58 · 장점과 전제
큰 정렬 배열 검색에 유리하지만, 미리 정렬해야 합니다. 배열 삽입은 원소 이동에 오 엔이 들 수 있어요.

## 화면에 표시하는 최소 Python 코드

```python
while lo <= hi:
    mid = (lo + hi) // 2
    if A[mid] == x:
        return mid
    if A[mid] < x:
        lo = mid + 1
    else:
        hi = mid - 1
return -1
```

`lo`와 `hi`는 모두 포함되는 경계입니다. `lo <= hi`인 동안 가운데를 검사합니다. 정렬 배열이 전제입니다. 삽입에서 `O(n)`은 배열의 원소를 실제로 이동시키는 비용이며, 이진 탐색으로 위치를 찾는 비용과는 별도입니다.

## 숫자 추적 검산

`A = [-1, 0, 3, 5, 9, 12]`, 목표 `x = 9`, 인덱스는 0부터입니다.

| 비교 | `lo` | `hi` | `mid` | `A[mid]` | 동작 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 0 | 5 | 2 | 3 | `3 < 9`, `lo = 3` |
| 2 | 3 | 5 | 4 | 9 | 찾음, `return 4` |

최선 시간은 `O(1)`, 평균·최악 시간은 `O(log n)`, 반복문 추가 공간은 `O(1)`입니다. 최악 비교 횟수는 `floor(log₂ n) + 1` 이하이므로 백만 개도 최대 20회 비교합니다. Big O는 정확한 횟수가 아니라 입력 크기에 따른 증가율입니다.
